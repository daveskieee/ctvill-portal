1. ROOT CAUSE ANALYSIS
--------------------------------------------------------------------------------
Observed Bug:
When an authenticated user on any role refreshed the browser (F5 / hard reload),
the public marketing Landing Page briefly appeared before the application returned
to the dashboard.

Underlying Technical Root Causes:
1. Implicit / Conflated Authentication State:
   In `src/App.tsx`, the active session state was modeled as:
     const [session, setSession] = useState<UserSession | 'login' | null>(null);
   Here, `null` was overloaded to represent two mutually exclusive scenarios:
     a. An unauthenticated guest visitor browsing the public Landing Page.
     b. An initializing / in-flight state while checking whether an existing
        session exists in the browser's HttpOnly session cookie.

2. Asynchronous Network Gap:
   On every page reload or hard refresh:
     - React initialized `session` synchronously to `null`.
     - `renderActiveWorkspace()` evaluated:
         if (session === null) {
           return <LandingPage onEnterPortal={() => setSession('login')} />;
         }
     - The browser immediately mounted and rendered `<LandingPage />` (including
       hero banners, marketing carousels, and public showcases).
     - Concurrently, `useEffect` fired `fetch('/api/auth/me')` asynchronously.
     - 50–250ms later, the HTTP response returned with the authenticated user session.
     - `setSession(data.session)` triggered a re-render, unmounting `<LandingPage />`
       and mounting `<AdminPortal />`.
   This produced the temporary flash of the public landing page on every refresh.

3. Unscoped Mount Requests (Premature Queries & SSE):
   `reloadAllData()` and `connectSSE()` were invoked unconditionally in `useEffect` on
   initial component mount, regardless of whether the user was authenticated.
   For unauthenticated visitors or during in-flight verification, this fired requests
   to `/api/all-data` and `/api/events`, receiving 401 Unauthorized responses and
   triggering redundant session cleanup handlers and false expiration alerts.

4. Route / Module Amnesia on Refresh:
   In `src/components/AdminPortal.tsx`, `activeTab` initialized directly to the role's
   default home (e.g. 'dashboard') without inspecting the active URL hash or
   session storage during `useState` initialization.
   Furthermore, sidebar clicks updated local component state without writing back to
   `window.location.hash` or `sessionStorage`. On refresh, users lost their active module
   context (e.g. Gantt, RFIs, Timekeeper attendance, Payroll) and were reset to the home tab.

--------------------------------------------------------------------------------
2. ARCHITECTURAL & CODE IMPLEMENTATION
--------------------------------------------------------------------------------
1. Explicit 3-State Authentication State Machine:
   Replaced overloaded `session` state with explicit `AuthStatus`:
     type AuthStatus = 'checking' | 'authenticated' | 'unauthenticated';
     - 'checking': The application is strictly verifying the session with
       backend `/api/auth/me`. During this state, the minimal CTVILL
       `SessionVerificationScreen` is rendered. The Landing Page and Login Portal
       are NEVER rendered during this state.
     - 'authenticated': The server has cryptographically verified the session
       via HttpOnly cookie. Renders `<AdminPortal />`.
     - 'unauthenticated': No valid session exists. Renders `<LandingPage />` or
       `<LoginPortal />` based on `unauthView`.

2. Minimal CTVILL Branded Loading Screen (`SessionVerificationScreen.tsx`):
   Created a dedicated, lightweight, theme-aware loading component that displays:
     - Authentic CTVILL enterprise logo (`logoJpg`) with ambient gold/amber pulse ring
     - "CTVILL ENTERPRISE • Project Management Operations" badge
     - Sleek animated spinner and "Verifying secure workspace session..." indicator
     - Zero public marketing content, zero login inputs, zero data exposure
     - Unmounts cleanly the instant `/api/auth/me` resolves.

3. Module Route Preservation & Browser History Synchronization:
   In `src/components/AdminPortal.tsx`:
     - Initial `activeTab` state inspects `window.location.hash`, query parameters (`?tab=`),
       `sessionStorage('ctvill_active_tab')`, and pathname against a canonical
       `routeMap` and verifies vertical RBAC permissions via `canAccessModule(role, tab)`.
     - An active synchronization effect maintains bidirectional lockstep between
       `activeTab`, `window.location.hash` (e.g. `#gantt`, `#rfis`, `#timekeeper-attendance`),
       and `sessionStorage`.
     - Listens to `hashchange` and `popstate` events to provide seamless browser
       Back / Forward navigation.

4. Protected Data Scoping & SSE Lifecycle:
   - `reloadAllData()` is triggered ONLY when `authStatus === 'authenticated'`.
   - `connectSSE()` is connected ONLY when `authStatus === 'authenticated'`, and
     tears down immediately upon logout or session invalidation.
   - `/api/auth/me` is excluded from the global 401 fetch interceptor in `apiClient.ts`
     to prevent duplicate session revocation alerts and redirect loops.
   - When a session expires, client redirects cleanly to `<LoginPortal />` with an
     informative security audit notice, strictly preventing access to protected data.
